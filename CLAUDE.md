# SweetEscape Music Player — working notes

Static site, no build step. Everything ships from `public/` and is deployed by Vercel.
There is no bundler, no package.json, no test suite. Edit the file, reload the page.

## Layout

| Path | What it is |
|---|---|
| `public/index.html` | The whole app's markup, including every modal (~1.5k lines) |
| `public/script.js` | One class, `AdvancedMusicPlayer`, plus a module-level `UI` factory (~15k lines, 600 KB) |
| `public/style.css` | Feature styles. Machine-formatted: selectors are merged into shared groups, so one class's rules are scattered across many blocks |
| `public/ui-system.css` | Design system. Loads **after** style.css and is authoritative for shared chrome |
| `public/script/settings.js` | Settings modal behaviour, lazy-fetched on first open |
| `public/karaoke.html` + `karaoke-styles.css` + `karaoke-player.js` + `karaoke-encoder.js` | Standalone karaoke share page |
| `public/sw.js` | Service worker. `STATIC_ASSETS` must list any new top-level asset; `NETWORK_ONLY_PREFIXES` lists paths it must never cache |
| `public/introduction.html`, `public/tutorial.html` | Static SEO pages served at `/introduction` and `/tutorial`, styled by `public/learn/learn.css`, screenshots in `public/learn/shots/` |
| `public/guide/` | Guide mode (`guide.js` module, `guide.json` content, `guide.css`). Fetched only on Alt+Shift+G or `/?guide`, never cached |
| `api/` | Vercel serverless functions (`youtube`, `deezer`, `musixmatch`, `shazam`, `download`, `count`, `gemini`, `song/[videoId]`, `youtube-iframe-api`) |
| `public/llms.txt` | Plain-text summary of the site for AI assistants; keep it in step with `introduction.html` |
| `vercel.json` | Rewrites + the immutable `Cache-Control` regex for hashed-forever assets |
| `CODEMAP.md` | **Generated** index of every method, element alias and dialog — read this before searching `script.js` |
| `ARCHITECTURE.md` | Class overview and the full UI design system reference |
| `scripts/` | Dev tooling (below) + `update-billboard.js`, run by a GitHub Action |
| `archive/` | Outdated reference copies, not deployed. `scriptforcoding.js` is an old commented `script.js` — don't edit it or treat it as current |

## Finding things without burning tokens

`public/script.js` is 600 KB across ~15k lines, and 54 of those lines are longer than
300 characters (the machine-formatted `innerHTML` template literals — the longest is
3.9 KB). **A single `grep -n` that hits a few of them dumps tens of kilobytes.**

- Start from `CODEMAP.md`: 567 methods grouped by topic, the `this.elements` keys whose
  names differ from their DOM id, and every dialog id with its line in `index.html`.
  Regenerate with `node scripts/codemap.js` (<1s) if it looks stale.
- Search with `grep -o`, or pipe through `cut -c1-200`, and only widen once you know
  which line you want.
- Read by range — `sed -n '1200,1260p'` — rather than opening the whole file.

## House rules

- **No comments** in source files — none of the CSS, JS or HTML carries them. Do not add any.
- **No unused CSS.** Every selector must resolve to something in the HTML or JS.
- Every change gets a version bump: append one line to `public/changelog.md` ending in
  `vX.Y.Z`, and commit with `vX.Y.Z: <summary>`. `current-version.txt` is regenerated by
  the `Update Version File` workflow from the last version in the changelog — matching it
  by hand is fine but not required.
- Commit on `main`. Attribution trailer per the session reminder.
- Regenerate `CODEMAP.md` when you add, remove or rename a method.
- **No `console.log`** in shipped code. Use `console.warn` / `console.error` only for a real
  problem the user or a developer should see.

## API caching and quota

YouTube search quota is the scarcest resource, so repeats are served from Vercel's edge:

- `api/youtube.js`, `api/deezer.js` and `api/musixmatch.js` set `s-maxage` on successful
  responses only. Errors, quota failures and Deezer's `artist_radio` (random on purpose, it
  powers Mix Lab's New picks) are never cached. Keep that split when adding a type.
- The edge cache keys on the full URL, so a cacheable request must be deterministic.
  YouTube calls take their first key from `youtubeKeyIndexFor(query, attempt)` (a hash of
  the query) and only randomise retries. Never put `Math.random()` or a timestamp in a
  cacheable API URL.
- A key that answers 403 goes into `exhaustedYouTubeKeys` and is skipped for the session.
- Third-party scripts are pinned to exact versions (`@supabase/supabase-js@2.118.0`,
  `pako@2.1.0`), which jsDelivr serves `immutable`. Don't use a range like `@2`.

## Editing: the files are CRLF

Every tracked text file uses CRLF. A patch script that searches for a multi-line string
built with `\n` will silently match nothing — convert the needle and the replacement to
`\r\n` first:

```js
const cr = t => t.split('\r\n').join('\n').split('\n').join('\r\n');
```

The same applies to heredocs and `printf` when appending to `changelog.md`.
Note that a `\n` inside a template literal in `script.js` is a **literal two-character
`\n`** in the file, not a newline — those single-line `innerHTML` strings are full of
`\n\t` sequences that must be matched verbatim.

## UI work

Read the "UI Design System" section of `ARCHITECTURE.md` first. Short version:

- Build dialogs from `.ui-overlay` / `.ui-modal` / `.ui-modal__header|__title|__close|__body|__footer`,
  `.ui-btn` (+`--primary|ghost|danger|sm|block`), `.ui-input`, `.ui-card`, `.ui-tab`, `.ui-chip`.
- In JS use the `UI` factory at the top of `script.js`:
  `UI.modal({title, icon, size, className, bodyClassName})` →
  `{overlay, shell, header, heading, body, footer, close, addFooter, open}`,
  and `UI.button(label, {variant, size, icon, block, onClick})`.
- Overlays open with `display: flex` (inline style, or an existing `.active` /
  `.subtitles-import-modal-show` class). Never `display: block`.
- Icons are Font Awesome 6.0 **local** (`public/all.min.css`) with an explicit prefix:
  `fas` / `far` / `fab`. FA4/FA5 names like `fa-star-o`, `fa-magic`, `fa-refresh` are gone —
  don't reintroduce them. Karaoke page loads FA from cdnjs instead.

### Cascade gotchas

`style.css` is full of `.someclass button` (0,1,1) rules that outrank a bare `.ui-btn`
(0,1,0). That is why the primitives are written as `.ui-btn, button.ui-btn, a.ui-btn`,
the header parts are scoped `.ui-modal__header .ui-modal__title`, and the legacy alias
uses `.modal button:where(:not(.ui-modal__close)):where(:not(.ui-btn))` — `:where()`
keeps that selector at (0,1,1) so modifiers still win. If a new style "doesn't apply",
check specificity against `style.css` before adding `!important` (there are almost none
in the codebase; keep it that way).

### Glass mode (`data-surface="glass"` on `<html>`)

An element with `backdrop-filter` (or `filter`, `opacity < 1`, `mask`) becomes a *backdrop root*:
a glass popover nested inside it can only blur what is inside that ancestor, so page content
behind the popover shows through sharp. If a glass wrapper contains a dropdown, put the
wrapper's blur on a `::before` (`position: absolute; inset: 0; z-index: -1`) instead, as
`.library-search-wrap` does in `ui-system.css`. Beware that this changes how glass children
look: a child with its own `backdrop-filter` used to sample only the wrapper's tint and now
samples the whole page, so the search input needed an explicit background and no blur to keep
its old colour. Pixel-diff the before/after (serve the old CSS with `page.route`) instead of
eyeballing it. Test glass by setting
`musicPlayer.appearance.surfaceStyle = 'glass'` then `musicPlayer.applyAppearance()`, and walk the
popover's ancestors for those properties rather than trusting a screenshot.

### Text from external APIs

The YouTube Data API returns `snippet.title` / `channelTitle` HTML-escaped. Anything from
an API goes through `decodeHtmlEntities()` **at the ingest point**, then `escapeHtml()`
on the way into markup — never hand-rolled quote replacement, and never `escapeHtml` on
text headed for `textContent` or an input `value`.

## Verifying a change

No test suite. Do this instead:

```bash
node --check public/script.js public/script/settings.js public/sw.js public/karaoke-player.js public/karaoke-encoder.js
node scripts/audit-css.js      # unused selectors + orphan @keyframes; clean baseline is 0/0
node scripts/codemap.js        # refresh CODEMAP.md
node scripts/dev-server.js     # serves public/ on http://localhost:4173
```

Then drive the page with Playwright — the only way to catch cascade regressions.
Install it **into the scratchpad**, not the repo (the repo has no package.json):

```bash
npm install --prefix "$SCRATCHPAD" playwright@1.63.0
node "$SCRATCHPAD/node_modules/playwright-core/cli.js" install chromium
```

Write the driver script inside the scratchpad and run it from there — `node -e` from the
repo root cannot resolve `playwright`, and `cd`-ing into the scratchpad in a Bash call
gets reset.

Notes when driving the page:

- Wait ~3s after `load`, then remove the welcome modal: it auto-opens on an empty library.
  `document.querySelectorAll('.welcome-modal').forEach(m => m.remove())`
- `musicPlayer` and `UI` are top-level `const`s, so `typeof window.musicPlayer` is
  `undefined` but `page.evaluate(() => musicPlayer.foo())` works.
- A `/api/count` 404 and its `"not found" is not valid JSON` page error are expected
  locally — the serverless functions in `api/` do not run under the static dev server.
- Check both `data-theme="dark"` (default) and `"light"`, and 400px width for overflow.
- `page.route('**/youtube.com/oembed**', …)` stubs the metadata fetches, so the add-song
  and autofill paths can be tested without network or API keys.

## Privacy: no YouTube cookies

The intro and tutorial promise that listening sets no advertising or tracking cookies. Keep it true:

- Every `new YT.Player` passes `host: AdvancedMusicPlayer.YOUTUBE_HOST` (`youtube-nocookie.com`), and plain
  embeds use `youtube-nocookie.com/embed/`. The karaoke page and `api/song/[videoId].js` do the same.
- Pages load the IFrame API from `/api/youtube-iframe-api`, which re-serves YouTube's loader without its
  `Set-Cookie` headers. The inline `onerror` fallback to `www.youtube.com/iframe_api` only runs if that
  function fails. Never point a script tag at `www.youtube.com` directly.
- Verify with a fresh Playwright context: play a song, then `context.cookies()` should hold nothing for
  `youtube.com` or `doubleclick.net`. The function does not run under the dev server, so stub
  `/api/youtube-iframe-api` with `route.fulfill` using the upstream body.

## Guide mode and the docs pages

- `script.js` only carries `setupGuideHotkey()` and `openGuide()`. Everything else lives in `public/guide/`
  and is pulled in with `import()` on demand. Keep it that way: nothing guide-related belongs in the
  always-loaded bundle.
- Guide text is data. To explain a new control, add a spot to `guide.json` (`target` selector, `title`,
  `body`, optional `keys`, `tips`, `prepare`, `fallback`). Put its id in `tour` only if the step-by-step
  tour should stop there; every spot with a `target` is used by Point and ask. `prepare` understands
  `tab`, `queue` and `sidebar` only; add new actions in `GuideSession.prepare`/`restorePrepared`.
- `vercel.json` sends `/guide/*` with `Cache-Control: no-store` and the service worker skips it, so a
  content change is live on the next press.
- When a feature changes, update `tutorial.html` (and `introduction.html` if it is a headline
  feature). Regenerate screenshots with the dev server running:
  `PLAYWRIGHT_PATH="$SCRATCHPAD/node_modules/playwright" node scripts/tutorial-shots.js [scene ...]`.
  It seeds a throwaway profile and proxies `/api/*` to production, so YouTube search uses real quota.

## Auditing CSS

`node scripts/audit-css.js` reports only; it never edits. It collects identifier tokens
from the HTML/JS (**not** from any `.css` file, or CSS-only classes look "used"), treats
a comma-group as live if any part is live, and honours *dynamic prefixes* — string
literals ending in `-`, so `'discord-badge state-' + state` keeps `.state-connected`
alive. `@keyframes` are checked against `animation-name` separately. Verify every hit by
hand before deleting.
